# 项目概览

> ⚠️ AI 首次接触项目时必须阅读本节，理解业务上下文后再读代码。

## 系统定位

一款轻量级、零外部运行库依赖的 Windows 系统 C 盘空间释放工具。它通过“智能扫描 -> 安全拷贝 -> Junction 目录联接占位”的核心流程，将 C 盘的重度文件夹安全转移至其他盘符，并维持原软件和系统的正常运作。

## 业务背景

现代软件与游戏体积急剧膨胀，导致普通 Windows 用户的系统 C 盘频繁面临容量红线。虽然 NTFS 文件系统支持通过目录联接（Junction）来转移大文件且不破坏原路径，但普通用户无法熟练使用命令行工具（如 `mklink`）。目前市场上类似工具多带有捆绑垃圾软件，或者打包体积过大、有复杂的依赖环境，开发一个兼顾**极端安全**与**轻量级无依赖**的工具是核心痛点。

## 项目目标

- **体积控制**：最终打包体积小于 10MB 的单文件绿色版可执行程序（`.exe`）。
- **极度安全**：跨盘数据迁移过程必须防丢数，包含事务日志与强有力的回滚机制。
- **极简操作**：普通用户“左-右”引导式一键操作，无需配置任何复杂参数。

## 核心业务关系

本项目中的组件协同依赖十分紧密。特别是在执行迁移和异常回滚时，跨模块的数据流关系如下：

| 模块 | 关联模块 | 影响方向 | 影响说明 |
|------|----------|----------|----------|
| `ui` (Slint 界面) | `engine` | `ui` → `engine` | 触发扫描、迁移、一键回滚操作；接收来自引擎的进度和滚动日志流。 |
| `engine` (迁移引擎) | `journal` | `engine` → `journal` | 执行数据物理拷贝前必须写入事务日志文件，完成或成功建立链接后清除日志。 |
| `engine` (迁移引擎) | `win_util` | `engine` → `win_util` | 强依赖 Windows 原生 API 适配，用于创建物理目录联接重解析点，并在复制前检查占用。 |

## 项目阶段

- **MVP 阶段 (Minimum Viable Product)**：
  优先保证单目录（Junction `/J`）迁移和异常保护，确保单文件提权执行正常，日志和撤回机制稳定。暂不考虑复杂的多文件硬链接支持（V1.5）。

# 健康度检查

定期或在重大变更后，执行以下检查：

```text
□ constraints.md 中的不变量是否与代码一致
□ 禁止事项是否被违反
□ 架构状态是否需要更新（代码重构后架构状态可能升级）
□ 术语是否在其他文档中一致使用
□ 是否存在超过 30 天未更新但代码已变更的约束
□ 代码实现与约束描述是否一致
□ 模块定位表（如存在）是否与当前代码结构一致
```

发现不一致时，优先更新知识库，再继续开发。

修改一个文档时，必须联动检查相关文档：

| 修改了 | 必须检查 |
|--------|----------|
| `constraints.md` | `glossary.md`、`boundaries.md`、`flows.md`、`lessons/` |
| `boundaries.md` | `constraints.md`、`flows.md` |
| `flows.md` | `constraints.md` Nic, boundaries.md、本文件（核心业务关系） |
| `glossary.md` | `constraints.md` |
| 本文件（核心业务关系） | `boundaries.md`、`flows.md` |

联动检查不意味着必须修改，而是确认是否需要同步更新。
