# ADR-003: 采用 vue-i18n 实现应用国际化

## 状态

Accepted

## 背景

CDiskLinker 前端基于 Vue 3 + Naive UI 构建。在国际化改造前，所有 UI 文案与运行日志均以中文硬编码散落于各组件与 store 中，存在以下问题：

1. **无法适配多语言用户**：应用面向 Windows 桌面用户，需同时支持中文与英文。
2. **文案与逻辑耦合**：硬编码文案混在模板与业务代码中，修改文案需触及逻辑代码，职责不清。
3. **日志不可翻译**：`stores/app.ts` 中的 `addLog` 直接拼接中文字符串，无法随语言切换动态翻译。
4. **与官网不一致**：官网已支持中英文切换（见 `docs/index.html`），应用层却仅中文，体验割裂。

需要一套国际化方案，统一管理多语言文案，并支持运行时切换。

## 方案选项

### 选项 A: 硬编码双份 UI 组件

为每种语言维护一套独立组件，通过路由或条件渲染切换。

优点：
- 实现直接，无额外依赖。

缺点：
- 文案修改需同步多套组件，维护成本极高。
- 违反 DRY 原则，组件逻辑易产生分歧。
- 日志系统仍需单独处理多语言。

### 选项 B: vue-i18n + 语言包 + 日志 i18n key 化

使用官方 `vue-i18n` 库，按模块组织语言包（`zh-CN.ts` / `en-US.ts`），组件中通过 `t('key')` 引用文案；日志系统改造为携带 `i18nKey` 与 `params`，由展示层 `LogConsole.vue` 负责翻译。

优点：
- Vue 官方生态方案，与 Naive UI 的 locale 机制天然协同。
- 文案集中管理，结构与模块职责对齐（common/lang/disk/tree/source/target/migration/journal/log）。
- 日志通过 key + params 解耦存储与展示，切换语言后历史日志亦可重新翻译。
- 语言偏好持久化到 `localStorage`，并支持浏览器语言自动检测。

缺点：
- 引入 `vue-i18n` 依赖（体积可接受，gzip 后约 30KB）。
- 需改造现有日志接口（`LogEntry` 新增 `i18nKey` / `params` 字段）。

### 选项 C: 自研简易字典

自建轻量字典对象，通过函数查表返回文案。

优点：
- 零依赖，体积最小。

缺点：
- 需自行实现复数、插值、响应式切换等能力，重复造轮子。
- 不与 Naive UI locale 联动，需额外胶水代码。
- 后续扩展语言时维护成本上升。

## 决策

选择 **选项 B (vue-i18n + 语言包 + 日志 i18n key 化)**。

理由：

1. **官方契合**：`vue-i18n` 是 Vue 官方推荐方案，与 Naive UI 的 `n-config-provider` locale/dateLocale 可直接联动，`App.vue` 中通过 `computed` 同步切换，无额外胶水成本。
2. **职责清晰**：语言包按业务模块组织，与现有组件结构对齐，符合"职责清晰"设计原则。
3. **日志解耦**：日志存储 `i18nKey + params`（语言无关），展示层负责翻译，遵循"变更隔离"——切换语言不需重写历史日志。
4. **避免过度设计**：仅支持中英文两种语言，不引入懒加载语言包等复杂机制（YAGNI），语言包直接同步 import。

## 实现要点

### 目录结构

```text
src/i18n/
├── index.ts            # i18n 实例、detectLocale、setLocale、toggleLocale
└── locales/
    ├── zh-CN.ts        # 中文语言包
    └── en-US.ts        # 英文语言包
```

### 语言包模块划分

按业务模块组织，与组件职责对齐：

| 模块 | 对应组件 | 内容 |
|------|----------|------|
| `common` | 通用 | 取消、确认、浏览等通用文案 |
| `lang` | 语言切换按钮 | 切换文案、语言名称 |
| `disk` | DiskOverview | 管理员状态、磁盘信息 |
| `tree` | TreeView | 目录树节点、加载状态 |
| `source` | MainView 源目录段 | 源目录标题、已选统计 |
| `target` | TargetSelector / MainView | 目标路径、盘符快捷、空间信息 |
| `migration` | MainView 操作区 | 迁移按钮、进度提示 |
| `journal` | JournalBar | 崩溃恢复 |
| `log` | LogConsole / stores/app.ts | 运行日志文案 |

### 日志系统改造

`LogEntry` 接口扩展：

```typescript
export interface LogEntry {
  timestamp: string
  level: 'info' | 'warn' | 'error' | 'success'
  i18nKey?: string              // 新增：语言无关的翻译键
  params?: Record<string, unknown>  // 新增：插值参数
  message: string               // 保留：fallback 原始文案
}
```

`LogConsole.vue` 中 `formatLogMessage` 优先使用 `i18nKey` 翻译，翻译失败回退到 `message`。

### 语言检测与持久化

- `detectLocale()`：优先读 `localStorage['app-locale']`，否则按 `navigator.language` 匹配，默认 `zh-CN`。
- `setLocale(locale)`：写入 `localStorage` 并切换 `i18n.global.locale`。
- `toggleLocale()`：在 `zh-CN` / `en-US` 间切换。

### Naive UI 联动

`App.vue` 中通过 `computed` 将 vue-i18n 的 `locale` 映射到 Naive UI 的 `zhCN` / `enUS` 与 `dateZhCN` / `dateEnUS`，确保内置组件（如日期选择器）同步切换。

## 影响

- **新增依赖**：`vue-i18n@^9.14.4`（见 `package.json`）。
- **新增模块**：`src/i18n/`，作为前端横切能力，不涉及 Rust 核心层。
- **接口变更**：`LogEntry` 新增可选字段 `i18nKey` / `params`，向后兼容（未提供时回退 `message`）。
- **架构边界**：国际化属 UI 层能力，不改变 `engine` / `journal` / `win_util` 等核心层职责，符合三层隔离约束。
- **扩展性**：未来新增语言只需在 `locales/` 增加语言包文件并更新 `detectLocale` 匹配逻辑，无需改动组件代码。

## 注意事项

- 语言包 key 必须保持中英文对称，新增文案时需同步更新两个语言包，避免出现 `t('key')` 返回 key 本身的情况。
- 日志的 `i18nKey` 应使用稳定的语义键，不应包含动态变量（动态内容通过 `params` 传递）。
- `localStorage` 的 key 为 `app-locale`，与官网的 `website-locale` 区分，互不干扰。
