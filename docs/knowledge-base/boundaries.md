# 能力边界

> **TL;DR**: 核心能力：智能扫描识别、双阶段安全迁移、文件独占解除。能力边界：本工具只负责文件物理转移和重解析点（Junction）创建，不干涉 Windows 自身的路径转发逻辑。⚠️ 易越界的边界：占用解除只提供在用户授权下的优雅/强制关闭进程服务，不负责进程重启失败的系统状态维护。

---

## 核心能力

### 智能扫描识别 (Smart Directory Scanning)

**能力定义**: 深度优先遍历（DFS）指定的 C 盘文件夹目录，自动过滤系统级黑名单，计算物理磁盘实际占用空间，并将可迁移项分级高亮。

**业务规则**:
- 自动屏蔽核心目录（如 `C:\Windows` 等），此规则不可被用户设置绕过。
- 扫描大小必须计算 `Size on Disk`（实际占用大小），需剥离稀疏文件与已有 Junction 重解析点的虚拟大文件大小，避免重复统计。

**对应代码**:
- `src/scanner.rs`

---

### 双阶段安全迁移 (Two-Phase Commit Migration)

**能力定义**: 执行将文件夹从 C 盘向其他磁盘的物理迁移，在源目录安全删除且重解析点成功创建之前，保障大数据的原子性以及可回滚性。

**业务规则**:
- **第一阶段（复制与校验）**：在目标盘写入以 `.tmp_` 为前缀的临时目录，对所有子文件执行物理拷贝，并进行哈希值和文件数量比对。
  - **默认模式**：拷贝时流式计算源端 SHA256（`copy_dir_recursive_with_hash`），目标端再次生成 Manifest 后 `verify_against` 逐项比对哈希、大小、数量。能检测磁盘静默位翻转。
  - **快速模式**（`fast_mode = true`）：仅校验文件数量与逐项大小（`generate_size_only` + `verify_size_only`），跳过 SHA256 计算。速度更快，但无法检测磁盘静默写入错误。默认关闭，仅 `Idle` 状态可切换。
- **第二阶段（链接与激活）**：在删除原 C 盘目录并成功创建 Junction 点之后，才可重命名激活目标盘上的临时文件夹。

**对应代码**:
- `src/engine.rs`
- `src/journal.rs`

---

### 文件独占解除 (File Lock Resolution)

**能力定义**: 迁移前扫描目标源文件夹，检测当前是否有其他应用程序进程独占访问，并提供优雅关闭或强制关闭占用进程的能力。

**业务规则**:
- 必须通过 Windows 的 Restart Manager API 提取占用当前文件的进程名和 PID。
- 必须在 UI 界面上提示受影响进程列表，经用户确认后方可关闭，禁止在后台静默强制关闭。

**对应代码**:
- `src/win_util.rs`

## 支撑能力

- **事务日志管理**：通过 `src/journal.rs` 对 `pending_jobs.json` 的读写，作为断电恢复和回滚的数据支撑。
- **迁移档案管理**：通过 `src/migration_history.rs` 维护已迁移目录的"迁移档案"，让软件能识别自己迁移过的目录，并提供软件内一键恢复入口。双副本设计：目标目录写入自包含指纹文件 `.cdisklinker_meta.json`（隐藏属性，跟随数据走），软件运行目录维护全局索引 `migration_history.json`（快速查询）。档案写入采用 best_effort 策略，失败不阻止迁移完成。

## 外部依赖能力

| 依赖 | 用途 | 替换成本 |
|------|------|----------|
| `Windows Win32 API` (`kernel32.dll` / `rstrtmgr.dll`) | 提供底层 Junction 创建、Token 获取提权、进程独占扫描服务。 | **极高**（与 Windows 深度绑定，无法在其他平台替代） |
| `Slint UI Engine` | 渲染极轻量的本地原生窗口与交互。 | **中**（可以通过重构 UI 层适配为 Tauri 等其他 GUI 框架） |

## 系统边界

### 系统内（我们负责）

- 文件夹数据的完整、无损跨盘物理拷贝与完整性校验。
- C 盘原位置 Junction（重解析点）的创建与删除。
- 迁移失败或中途故障时的数据回滚与状态恢复。

### 系统外（外部负责）

- 文件复制时 Windows 系统底层 NTFS 的实际 I/O 扇区读写与防丢数（由操作系统内核保证）。
- 外部应用软件通过 Junction 读取大文件时的读写转发（由 Windows 重解析点分发机制处理，我们不介入路径转发代理）。

## 扩展点分析

| 扩展点 | 当前实现 | 未来可能 | 扩展方式 |
|--------|----------|----------|----------|
| **硬链接文件迁移** | V1.0 仅支持 Junction 目录联接（跨盘文件夹） | V1.5 支持跨盘文件单体硬链接（Hard Link） | 在 `win_util` 模块增加 `create_hard_link` 接口，并引入文件级别的路由判断。 |
| **文件扩展名过滤** | 对整个文件夹下的内容全部物理移动 | V1.5 允许用户过滤特定扩展名（如只把视频迁移走，保留配置） | 在 `scanner` 及 `engine` 中追加 `ExtensionFilter` 策略规则。 |
| **智慧推荐迁移算法** | 仅按文件大小和警告级别分级展示 | V2.0 基于历史数据与算法，智能评估“非系统依赖的大文件”推荐级别 | 重构 `scanner`，新增评估接口并支持插入推荐算法实现。 |
| **迁移档案全局索引自动重建** | 全局索引 `migration_history.json` 丢失时无自动恢复 | V2.0 启动时扫描所有盘符的 `.cdisklinker_meta.json` 重建全局索引 | 在 `migration_history` 模块新增 `rebuild_index_from_meta_files` 函数，启动时调用。 |
| **迁移档案加密与签名** | 档案仅用 SHA256 自哈希防篡改 | V2.0 增加非对称签名，防止伪造档案 | 在 `MigrationArchive` 结构体增加 `signature` 字段，引入签名/验签机制。 |
